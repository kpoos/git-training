# 06 — Team capstone

## Goal

Complete a small, end-to-end contribution as a team: plan it, implement it on
a branch, review it, and merge it.

## Choose a practice project

Use a disposable repository such as a team glossary, event checklist, or
collection of short how-to notes. Agree on contribution rules: file format,
where content belongs, naming conventions, and how a change is checked. Do not
use private or production data.

## Team workflow

1. Create one issue per small contribution and agree on acceptance criteria.
2. Assign author and reviewer roles; rotate roles between contributions.
3. Create one branch per issue from the up-to-date default branch.
4. Make a focused change and inspect the staged diff before committing.
5. Push the branch and open a PR that references its issue.
6. Review the diff using the checklist from module 04.
7. Resolve feedback, verify the final diff, and merge after approval.
8. Update local branches and confirm the change is present.

## Completion checklist

- [ ] Each contribution traces to an issue or agreed task.
- [ ] Commits are focused and have descriptive messages.
- [ ] PR descriptions explain the change and how it was checked.
- [ ] At least one teammate reviewed each contribution.
- [ ] Review feedback was resolved or explicitly discussed.
- [ ] No secrets, unrelated changes, or accidental files were introduced.
- [ ] The team can explain how the merged change appears in Git history.

## Team retrospective

Discuss:

- Where did communication prevent a Git problem?
- Which command or GitHub screen gave the most useful information?
- Did any PR become too large or difficult to review?
- What would the team put in a contribution guide before doing this work again?
